ATELIER FAYET 33 — MISE À JOUR 25

NOUVELLES FONCTIONS
1. Ruptures : dans Modifier la liste, administrateur et modérateurs peuvent cocher Article en rupture pour chaque ligne. Enregistrer avant validation. Tous les collaborateurs voient la mention, mais seuls admin/modérateurs peuvent la changer.
2. Après Développer, Valider la demande apparaît à droite de Modifier la liste pour admin/modérateurs. Il n’est pas nécessaire d’ouvrir le formulaire.
3. Sous le titre : Validée par [nom] le [date] à [heure], heure de Paris.
4. Une commande validée est consultable, mais plus modifiable par les collaborateurs. Admin/modérateurs peuvent la corriger ; la correction la remet en attente et doit être validée à nouveau. Les droits sont contrôlés dans Supabase, pas seulement dans l’interface.
5. Exporter en PDF dans la commande : numéro de semaine, année, articles, quantités, ruptures, statut, validation et dates.
6. Exporter la fiche en PDF dans le détail d’un signalement : immatriculation, auteur, date de saisie, date de modification éventuelle, notes et toutes les photos. Chaque photo a sa page. Les droits de consultation des signalements restent identiques.
7. Ratio du jour à droite du cadre objectif, uniquement pour les membres de l’équipe métier Encadrants, selon la date sélectionnée. Le rôle admin/modérateur seul ne suffit pas. Le ratio est extrait de la ligne sous l’objectif dans le PDF Orquest et peut être vérifié/corrigé dans l’aperçu d’import. Une valeur non reconnue reste vide, elle n’est pas devinée.

INSTALLATION DEPUIS MAJ24

1 — SUPABASE
Ouvre supabase/25-consommables-ratios.sql, copie tout le contenu dans SQL Editor, puis Run. Attends le succès. Réexécution possible.
Ce script ajoute les ratios et les nouvelles règles de commandes. Il conserve les fonctions actuelles de chargement et d’import pour préserver les horaires et les évolutions précédentes.
Ne réexécute pas une ancienne migration après celle-ci.
Le programme hebdomadaire MAJ24 reste actif, aucun changement nécessaire.

2 — GITHUB
Remplace :
- package.json
- package-lock.json
- src/order-requests.tsx
- src/reports.tsx
- src/workshop.tsx
- src/planning-import.tsx
- src/lib/orquest-parser.ts
- src/globals.css
Ajoute :
- src/lib/pdf-export.ts
- public/fonts/export-sans.ttf
- public/fonts/LICENSE.txt
- supabase/25-consommables-ratios.sql
La nouvelle dépendance PDF est installée automatiquement pendant le build Cloudflare : il faut impérativement envoyer package.json ET package-lock.json.
Tu peux aussi envoyer tous les fichiers du ZIP en conservant les dossiers.

3 — CLOUDFLARE
Attends le succès du déploiement, puis recharge l’application.
Aucune nouvelle variable ou Edge Function.

4 — IMPORTER LES RATIOS
Les anciens imports ne contenaient pas les ratios : renvoie ton PDF dans Importer un planning PDF.
Vérifie les valeurs sous les objectifs dans l’aperçu.
Tu peux laisser Remplacer décoché : les horaires/objectifs existants sont conservés et les ratios absents sont ajoutés.
Pour corriger un ratio existant par import, l’option Remplacer s’applique aussi aux horaires et objectifs sélectionnés : vérifie les cases avant validation.
Pour voir le ratio, ta fiche doit appartenir à l’équipe Encadrants.

EXPORTS PDF
Le PDF est généré sur l’appareil, puis enregistré ou proposé au téléchargement par le navigateur. Les photos ne sont pas envoyées à un service externe pour cet export. L’export utilise les dernières données affichées/enregistrées, pas un formulaire non enregistré.

VÉRIFICATIONS
Compilation, tests SQL des droits/ruptures/verrouillage/ratios, lecture du ratio sur le PDF Orquest fourni, essais navigateur pour les quatre profils, téléchargement et rendu des PDF (photos, accents, textes longs et sauts de page).
Le ZIP n’est pas automatiquement déployé.

QUESTION SUR L’ACCÈS AU COMPTE D’UN COLLABORATEUR
Aucune connexion à la place d’un collaborateur n’est ajoutée dans cette version. Une fonction distincte Voir comme ce collaborateur, en lecture seule, peut être ajoutée pour l’assistance sans changer de compte ni agir en son nom.
