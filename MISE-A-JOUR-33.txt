Gestion des réponses et personnalisation des boutons

1. Supabase > SQL Editor > New query : copier et exécuter
   supabase/33-sondages-boutons.sql.
   Le script est réexécutable et conserve les données existantes.
2. Décompresser ce ZIP et remplacer les fichiers du projet dans GitHub.
3. Attendre le déploiement Cloudflare puis recharger l’application.
Aucun secret, variable de build ou déploiement Edge Function à modifier.
Si la MAJ32 n’est pas installée, exécuter d’abord son script SQL.

1 — RÉPONSES NOMINATIVES ET SUPPRESSION DES SONDAGES
Dans un sondage nominatif, l’administrateur et les modérateurs peuvent :
- cliquer Modifier sur une réponse, choisir une autre option et enregistrer ;
- supprimer individuellement une réponse après confirmation ;
- supprimer le sondage entier, anonyme ou nominatif, et toutes ses réponses.
La suppression du sondage est aussi accessible depuis la liste des sondages.
Les corrections restent possibles sur un sondage fermé.

Une correction indique le nom du gestionnaire et la date/heure de Paris.
La personne concernée voit également cette indication sur sa propre réponse.
Si elle répond à nouveau à un sondage ouvert, son nouveau choix remplace
la correction : une seule réponse est conservée par personne.
Une réponse supprimée peut être saisie à nouveau par son auteur tant que
le sondage est ouvert. Les résultats sont recalculés après chaque action.
Si quelqu’un modifie une réponse entre son affichage et la correction,
l’application demande d’actualiser pour éviter d’écraser le changement.

Les réponses anonymes restent inaccessibles individuellement : on ne peut
pas consulter, corriger ou supprimer une réponse anonyme particulière.
La suppression complète du sondage anonyme reste possible.
Le mode anonyme/nominatif reste verrouillé après la première réponse,
même si toutes les réponses sont ensuite supprimées.
La suppression d’un sondage masque les boutons personnalisés qui utilisent
son lien standard (?poll=identifiant). L’administrateur peut les supprimer
ou leur attribuer un autre lien dans Gérer les boutons.

2 — BOUTONS PERSONNALISÉS
Le pictogramme de lien externe est retiré des raccourcis personnalisés.
Administration > Gérer les boutons > créer ou modifier un bouton :
- cocher « Personnaliser la couleur du bouton » ;
- choisir la couleur et vérifier l’aperçu ;
- enregistrer.
Le texte devient automatiquement noir ou blanc selon la couleur pour
rester lisible. La couleur choisie s’applique aussi en mode sombre.
Décocher l’option permet de revenir aux couleurs habituelles du thème.
La gestion des boutons reste réservée à l’administrateur.

3 — BOUTON SIGNALER
Fond rouge très clair #fee2e2, contour rouge foncé #991b1b,
texte rouge foncé, comme le cadre d’urgence en mode clair.
Cette apparence claire du bouton est conservée en mode sombre.
Les pages sur lesquelles ce raccourci est masqué restent inchangées.

4 — WORKORDER : LIMITE DE L’IFRAME
Vérification effectuée sur l’URL fournie le 14 octobre 2026 :
https://smartworkshop.digiforce.io/workorders-view/
La requête sans session est redirigée vers la connexion Google.
Cette page de connexion renvoie X-Frame-Options: DENY, ce qui interdit
son affichage dans une iframe. Ajouter width, height ou title dans le
code HTML ne lève pas cette restriction.
L’intégration complète avec connexion ne peut donc pas fonctionner dans
une page intégrée de l’application avec ce parcours actuel.
L’affichage après une authentification existante chez WorkOrder n’a pas
été vérifié avec ton compte ; il ne faut pas le considérer comme garanti.
Cette mise à jour conserve l’ouverture actuelle de WorkOrder et n’ajoute
pas une page iframe qui bloquerait la connexion. Aucun contournement des
protections Google ou de WorkOrder n’est mis en place.
