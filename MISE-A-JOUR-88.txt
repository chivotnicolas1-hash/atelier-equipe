ATELIER FAYET 33 — MISE À JOUR 88 FINALE

À appliquer après la version 87. Cette archive remplace les archives intermédiaires « étape 1 », « étape 2 », « étape 3 » et « étape 4 ».

1 — SUPABASE
Dans SQL Editor, exécuter dans cet ordre les trois scripts de cette archive :
1. supabase/88a-reautorisation-pc.sql
2. supabase/88b-classement-ruptures.sql
3. supabase/88c-codes-catalogue.sql
Attendre Success à chaque étape. Réexécuter ces versions même si une étape intermédiaire a déjà été installée : elles sont réexécutables et le 88c contient une nouvelle lecture groupée des codes.
Aucune commande ni vente n’est supprimée par ces scripts.

2 — GITHUB / CLOUDFLARE
Remplacer les fichiers du projet par ceux de cette archive.
Les fichiers du projet sont directement à la racine du ZIP : ne pas créer un sous-dossier supplémentaire dans GitHub.
Dans GitHub Desktop : Commit puis Push origin. Attendre le déploiement Cloudflare réussi.
Conserver les variables de build existantes. Aucune nouvelle clé ni Edge Function à déployer.
Ne pas ajouter de fichier _redirects.
Fermer et rouvrir l’application après déploiement.

3 — PC AUTORISÉS
Administrateur > Paramètres application > Écran atelier au démarrage · PC autorisés.
Sur un PC dont l’autorisation a été retirée : Réautoriser ce PC.
L’autorisation existante est réactivée pour un an. Le navigateur concerné doit avoir conservé son jeton local.
Si les données du navigateur ont été effacées ou si l’ouverture automatique a été désactivée localement, reconnecter un administrateur sur ce PC et utiliser Autoriser ce PC et tester l’ouverture.
La réautorisation est réservée à l’administrateur dans Supabase.

4 — CODES PRODUIT
Administrateur > Consommables > Pneus, 5gaz ou Freins, transmissions, roulements > Modifier le catalogue.
Modifier Code produit puis Enregistrer le code. Les zéros initiaux sont conservés.
Le code doit contenir de 1 à 100 caractères. En cas de modification simultanée, l’application demande de rouvrir le catalogue.
Les codes restent réservés à l’administration et à la modération pour les commandes ; leur modification reste réservée à l’administrateur.
Le chargement des codes se fait en une requête par section, au lieu d’une par article.

5 — RÉSEAU ET PHOTOS
Les messages réseau disparaissent après une lecture réussie.
Les lectures des consommables retentent une fois sur un échec réseau temporaire ; la synchronisation reprend également au retour d’Internet et toutes les 20 secondes.
Les données déjà chargées restent affichées. Les écritures ne sont jamais répétées automatiquement : après une coupure pendant un enregistrement, vérifier la commande avant de réessayer.
Les photos de catalogue, y compris des huiles, apparaissent à gauche du nom dans les commandes en cours et validées, sans déformation, en miniatures de 30 à 46 px.
Les photos chargées par les catalogues sont réutilisées, sans télécharger trois fois les mêmes catalogues pour les commandes.
Une ligne sans photo disponible reste affichée normalement. Pour les anciennes lignes sans identifiant produit connu, une correspondance de nom non ambiguë est utilisée ; une désignation modifiée ou ambiguë peut donc ne pas afficher de photo.

6 — PRODUITS LES PLUS COMMANDÉS
Le classement compte les commandes validées non supprimées, en excluant chaque ligne signalée en rupture lors de la commande.
Un produit ayant été réellement commandé auparavant reste compté pour ces anciennes commandes, même s’il est aujourd’hui en rupture dans le catalogue.
Les doublons d’un produit dans une même commande ne gonflent pas le nombre de commandes.
