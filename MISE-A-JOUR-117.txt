ATELIER FAYET 33 — MISE À JOUR 117
CIBLES, HISTORIQUES DES ENLÈVEMENTS, PHOTOS ET RÉCUPÉRATION DU COMPTE

Cette archive contient l’application complète, basée sur la version 116
(dont l’accueil plus compact et le raccourci Mes tâches), avec le pictogramme
voiture de la 115. Atelier Toolbox 33 n’est pas inclus.
La base doit déjà être au niveau 113 et des migrations antérieures.
Les versions 115 et 116 ne nécessitaient aucun SQL.

1 — SUPABASE : LES DEUX SCRIPTS SQL
Dans ton projet Supabase, ouvre SQL Editor > New query.
Ouvre avec le Bloc-notes le fichier :
  supabase/117a-historique-dechets.sql
Copie TOUT son contenu dans la nouvelle requête, puis clique Run.
Attends la réussite.
Crée ensuite une deuxième requête et exécute de la même manière :
  supabase/117b-recuperation-mot-de-passe.sql
Les scripts sont transactionnels et réexécutables sans réinitialiser les codes
ou effacer les demandes. Ils ne suppriment aucun ancien signalement, aucune
photo, aucune demande de déchet ni aucun compte.
Ne réexécute pas les anciens SQL et ne réinstalle pas la 114.

2 — SUPABASE : CRÉER LA FONCTION workshop-recovery
La récupération d’un mot de passe doit être traitée par le serveur.
Mettre seulement les fichiers sur GitHub ne déploie pas une Edge Function.

Depuis le tableau de bord Supabase :
- Edge Functions > Deploy a new function > Via Editor.
- Nomme la fonction exactement : workshop-recovery
- Ouvre dans l’archive :
    supabase/functions/workshop-recovery/index.ts
- Remplace entièrement le code du modèle par le contenu de ce fichier.
  Un seul fichier index.ts suffit pour cette nouvelle fonction.
- Clique Deploy function et attends la réussite.
- Dans les détails / paramètres de CETTE fonction, désactive la vérification
  automatique JWT (Verify JWT / Enforce JWT verification), puis enregistre.
  C’est nécessaire pour le formulaire Mot de passe oublié, accessible avant
  connexion. Le code vérifie lui-même la session ET le mot de passe actuel
  pour générer un code ; la réinitialisation vérifie le code et les limites
  de tentatives. Ne change pas les réglages des autres fonctions.

Aucun nouveau secret à créer. SUPABASE_URL, SUPABASE_ANON_KEY et
SUPABASE_SERVICE_ROLE_KEY sont les variables serveur déjà fournies par
Supabase, comme pour tes fonctions de connexion et de gestion des comptes.
N’ajoute aucune clé service_role dans le site, GitHub ou une variable VITE.

3 — SUPABASE : METTRE À JOUR workshop-accounts
Toujours après les deux SQL :
- Edge Functions > workshop-accounts > Code.
- Remplace tout le code par celui du fichier de cette archive :
    supabase/functions/workshop-accounts/index.ts
- Clique Deploy updates et attends la réussite.
Cette modification annule le code de récupération existant lors d’une
réinitialisation du mot de passe par l’administrateur ou le responsable
autorisé à traiter une demande. Les créations de comptes sont conservées.
Garde le réglage JWT déjà en place pour cette fonction.
Ne redéploie pas workshop-push ni workshop-login : ils ne changent pas.

Si tu utilises déjà le CLI Supabase, alternative aux étapes 2 et 3,
depuis le dossier du projet lié à TON projet Supabase :
  supabase functions deploy workshop-recovery --no-verify-jwt
  supabase functions deploy workshop-accounts --no-verify-jwt
Le fichier supabase/config.toml fourni contient les paramètres correspondants.

5 — PREMIÈRE UTILISATION DU CODE PERSONNEL
Chaque personne doit faire cette préparation AVANT d’oublier son mot de passe :
- Se connecter normalement.
- Ouvrir Mon profil > Récupération de mon compte.
- Saisir son mot de passe actuel.
- Cliquer Générer mon code personnel.
- Copier le code ou télécharger le document texte proposé et le conserver
  dans un endroit sûr, séparé du mot de passe.
- Cocher J’ai conservé mon code, puis Terminer.
Le code ne sera plus consultable après fermeture de cette rubrique.
Il est à usage unique et valable un an. En générer un nouveau remplace l’ancien.
Aucun e-mail ni SMS n’est ajouté au compte.
La base ne conserve qu’une empreinte du code, jamais le code en clair.

6 — SI LE MOT DE PASSE EST OUBLIÉ
Sur l’écran de connexion : Mot de passe oublié ?
Renseigner l’ID de connexion, le code personnel, puis le nouveau mot de passe
et sa confirmation (12 à 128 caractères).
Le code peut être saisi avec ou sans tirets, en minuscules ou majuscules.
Après réussite, se connecter normalement avec le nouveau mot de passe.
Générer ensuite un NOUVEAU code dans Mon profil : le précédent est consommé.
Une notification dans Mes notifications informe de la réinitialisation.
Les limites de tentatives sont appliquées sur le serveur ; un dépassement
invite à attendre 15 minutes. La connexion normale garde son fonctionnement.
Le résolveur d’ID existant de la MAJ100 conserve aussi ses protections.
Les sessions renouvelables sont révoquées par Supabase lors du changement
administratif du mot de passe ; un JWT déjà délivré peut rester valide jusqu’à
son expiration, selon la configuration Auth du projet.

Si la personne n’a jamais préparé de code, ou a perdu le code aussi :
Je n’ai pas de code ou je l’ai perdu > Contacter mon responsable.
Le circuit de demande de réinitialisation déjà existant est conservé.
Une réinitialisation autonome à partir de l’ID seul n’est pas autorisée.

Si une erreur réseau empêche de confirmer le résultat, essayer d’abord la
connexion avec le nouveau mot de passe. Le code peut avoir été consommé.
En cas de refus explicite du nouveau mot de passe par Supabase, le code est
réactivé pour permettre de choisir un autre mot de passe. Une erreur ambiguë
ne réactive pas automatiquement un code qui pourrait avoir déjà été utilisé.

7 — DÉCHETS : HISTORIQUES DES ENLÈVEMENTS
Les historiques quittent les menus de chaque prestataire.
Ils se trouvent maintenant en BAS de la page Déchets, dans la rubrique
repliable Historiques des enlèvements.
Ouvrir la rubrique pour consulter les années et les familles de déchets.
Les filtres Année et Famille permettent d’affiner la recherche.
Le classement est par année décroissante, puis famille, avec les passages
les plus récents en premier dans chaque famille.
Les ramassages partiels sont inclus à leur date réelle, même si le restant
est toujours dans Demandes en cours. Les simples validations d’une demande
à ramasser ne sont pas comptées comme des enlèvements.
Une ancienne quantité absente reste indiquée Non renseignée, jamais inventée.
Le ramassage final correspond au solde enlevé lors du dernier passage.
L’historique est paginé par 50 lignes de déchets : un passage avec plusieurs
familles apparaît donc dans plusieurs familles. Les unités sont conservées.
Les demandes en cours et leurs actions restent dans Demandes en cours.
Les administrateurs/modérateurs retrouvent aussi les actions de la demande
associée dans les détails d’un enlèvement, selon les permissions existantes.
La consultation des anciennes familles supprimées du catalogue reste possible.

8 — PHOTOS DES SIGNALEMENTS
Toujours 5 photos maximum et 10 Mo maximum par photo.
Formats : JPEG, PNG et WebP. La reconnaissance utilise maintenant le contenu
réel du fichier, même si le téléphone ne fournit pas correctement son type.
Les photos sont préparées une par une, réduites et compressées pour rester
dans la limite actuelle de la base. Une image invalide n’arrête plus les autres.
Un secours de décodage existe pour les navigateurs qui n’acceptent pas
createImageBitmap redimensionné ; ce secours refuse les très grandes images
pour limiter les allocations mémoire. Utiliser le mode standard 12 Mpx.
HEIC/HEIF ne sont pas convertis par cette version : choisir le mode JPEG /
format compatible du téléphone ou exporter la photo en JPEG.
En cas d’échec d’envoi, les photos et le brouillon restent dans l’onglet.
Un délai maximum de 60 secondes évite une attente indéfinie.
Avant un nouvel essai, consulter l’historique pour éviter de confondre un envoi
échoué avec une réponse perdue alors que le serveur avait déjà enregistré.
Les nouvelles tentatives conservent l’identifiant du brouillon.
Les contrôles de certification et de signature restent inchangés.

9 — CIBLES DU JOUR
Un pictogramme très clair apparaît en fond de chaque cible : freins, batterie,
voiture pour géométrie, flocon pour climatisation et contrôle qualité.
Les cibles personnalisées ont un pictogramme reconnu par leur intitulé,
ou une cible générique quand leur nature ne peut pas être déterminée.
Les compteurs, délais, permissions et pourcentage ne changent pas.
Les pictogrammes sont aussi intégrés à l’affichage des cibles en mode écran.

10 — VÉRIFICATIONS APRÈS INSTALLATION
Sur un compte de test : générer un code, se déconnecter, utiliser Mot de passe
oublié, se connecter avec le nouveau mot de passe et vérifier que l’ancien
code ne fonctionne plus. Préparer un nouveau code ensuite.
Vérifier aussi la création/réinitialisation d’un accès par l’administrateur.
Tester un signalement avec plusieurs photos depuis le téléphone concerné.
Consulter un enlèvement complet et un enlèvement partiel dans l’historique.
Le rapport VERIFICATIONS-117.md décrit les contrôles locaux et leurs limites.
Aucune modification ni aucun déploiement sur ta production n’a été effectué.
