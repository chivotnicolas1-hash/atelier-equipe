MISE À JOUR 09 — SIGNALER UN VÉHICULE

INSTALLATION SUR LA VERSION 08
1. Décompresse atelier-supabase.zip.
2. Ouvre supabase/09-signalements.sql avec le Bloc-notes et copie tout.
3. Supabase > SQL Editor > New query : colle le script puis clique Run.
   Attends Success. Les migrations précédentes jusqu’à 07 doivent déjà
   être installées (la version 08 n’avait pas de script SQL).
4. Dans GitHub > src :
   - remplace workshop.tsx et globals.css ;
   - ajoute reports.tsx ;
   - clique Commit changes.
5. Ajoute supabase/09-signalements.sql dans le dossier supabase du dépôt
   pour garder la migration avec le projet, puis Commit changes.
6. Attends le succès du dernier déploiement Cloudflare et recharge le site.

Aucune modification de variable Cloudflare, fonction Edge, dépendance ou
configuration Supabase Storage n’est nécessaire.

UTILISATION
Dans l’espace Collaborateur, clique sur Signaler sous les indicateurs,
au même emplacement et avec le même style que Gérer l’annonce en Administration.
- Renseigne l’immatriculation (3 à 20 caractères : lettres, chiffres,
  espaces ou tirets ; elle sera enregistrée en majuscules).
- Ajoute un commentaire facultatif si nécessaire.
- Ajoute jusqu’à 5 photos facultatives : JPEG, PNG ou WebP, 10 Mo maximum
  par photo avant traitement. Un aperçu permet de retirer une photo.
- Clique Enregistrer le signalement.

La date et l’heure sont fixées automatiquement par Supabase à la validation.
Elles sont affichées avec les secondes, à l’heure de Paris.
Ce n’est pas une date d’incident saisie manuellement.
Une confirmation apparaît uniquement après l’enregistrement serveur.
Une nouvelle tentative identique après une erreur réseau ne crée pas
un second signalement.

L’onglet Signalements donne accès à l’historique, indépendamment de la date
affichée pour l’atelier. Clique sur une ligne pour voir le commentaire et
les photos. Les photos sont affichées en grand dans le détail.
L’historique est paginé par 30 signalements. Actualiser recharge la liste.
Le brouillon reste présent lorsque tu changes d’onglet dans l’application.
Enregistre-le avant de fermer ou recharger la page : il n’est pas sauvegardé
sur le serveur avant validation.

DROITS
- Collaborateur et modérateur : création et consultation de leurs propres
  signalements uniquement.
- Administrateur, vue Administration : consultation de toute l’équipe.
- Administrateur, vue Collaborateur : bouton Signaler et historique personnel.
- Les données et photos ne sont pas accessibles publiquement.
- Les droits sont contrôlés par Supabase, y compris lors de l’ouverture
  d’un signalement par son identifiant.
- Un compte retiré de l’équipe ne peut plus accéder à ces fonctions.
Cette version ne comporte pas de suppression/modification de signalements,
ni de notifications push ou d’envoi par e-mail.

PHOTOS
Les images gardent leurs proportions, sans recadrage. Elles sont réduites
à 1280 pixels maximum sur le grand côté et compressées en JPEG avant envoi.
Elles sont stockées avec le signalement dans Supabase, pas seulement dans
le navigateur. Les photos originales ne sont pas conservées par l’application.
Les listes ne chargent pas les images : elles sont récupérées à l’ouverture
du détail pour limiter le volume de données transférées.

VALIDATION
Compilation de production ; tests SQL des droits, de la date serveur,
de l’enregistrement des photos, des limites de taille/nombre, de la pagination,
des nouvelles tentatives sans doublon et de la conservation après migration.
Tests Chromium sur données de démonstration avec les trois profils :
ouverture du formulaire, immatriculation/commentaire, photos et aperçu,
retrait d’une photo, brouillon entre onglets, enregistrement et consultation.

Le ZIP ne met pas automatiquement à jour Supabase, GitHub ou Cloudflare.
