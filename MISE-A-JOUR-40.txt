ATELIER FAYET 33 — MISE À JOUR 40
Profil, certification, plaques et débrief IA avec lecture vocale

INSTALLATION APRÈS LA MAJ39
1. Décompresse le ZIP.
2. Supabase > SQL Editor > New query : exécute dans cet ordre les contenus
   complets de ces deux fichiers :
   supabase/40-profils-signalements.sql
   supabase/40b-debrief-ia.sql
   Attends Success pour chacun. Les scripts sont réexécutables.
3. Pour l’IA, réalise l’activation décrite plus bas. Sans clé API, tous les
   autres changements fonctionnent ; le bouton IA affiche une explication.
4. Remplace sur GitHub les dossiers src, public, supabase et les fichiers
   de configuration fournis à la racine du ZIP.
   Conserve les variables Cloudflare et les secrets Supabase existants.
   Ne crée pas de fichier _redirects.
5. Attends la réussite du déploiement Cloudflare, puis ferme et rouvre l’appli.
   Il faut déployer le nouveau site après le SQL : les anciens formulaires
   sans certification ne peuvent plus enregistrer de signalement.

1 — MON PROFIL
Présentation en rubriques repliables :
- Carte d’identité : photo, nom, adresse et équipe.
- Photo de profil : choix, recadrage et suppression.
- Fonction et signature : intitulé professionnel et tracé de signature.
- Sécurité : changement du mot de passe.
- Notifications sur cet appareil, conservées en bas, puis déconnexion rouge.
Le bouton Configurer continue à amener directement aux notifications.
La photo peut être enregistrée sans fermer le profil.

La fonction est en lecture seule pour les collaborateurs et modérateurs.
Seul l’administrateur peut la changer, y compris côté serveur :
- sa propre fonction dans Mon profil ;
- celle d’un collaborateur via Équipes > Modifier la fonction.
Le compte doit avoir été créé pour enregistrer cette fonction personnalisée.
Les intitulés enregistrés précédemment sont conservés. Sans intitulé
personnalisé, l’équipe sert de valeur de repli.
Ce réglage ne modifie jamais les droits ou l’équipe du collaborateur.

2 — CERTIFICATION ET SIGNATURE AUTOMATIQUE
La question « Apposer ma signature » est supprimée.
Une case obligatoire la remplace :
« Je certifie l’exactitude des informations saisies ».
La date, l’heure et le nom de la personne qui certifie sont enregistrés.
La signature du collaborateur est automatiquement copiée depuis son profil
lorsqu’il crée ou corrige son propre signalement.
S’il n’a pas encore créé sa signature, la fiche peut être enregistrée après
certification mais reste sans signature : aucune signature n’est inventée.
Il peut ensuite créer sa signature dans Mon profil puis corriger/certifier
à nouveau sa fiche pour l’y apposer.

Une correction par l’administrateur sur la fiche d’un autre collaborateur
retire l’ancienne signature sans utiliser celle de l’auteur à sa place.
L’auteur peut certifier à nouveau pour réapposer sa signature enregistrée.
Les signatures déjà copiées sur les fiches ne changent pas lorsque le profil
est modifié. Les anciennes fiches ne sont pas certifiées rétroactivement.

3 — PLAQUES D’IMMATRICULATION
PDF : cadre réduit, proportions allongées, police Barlow Condensed SemiBold,
lettres et chiffres noirs, tirets, bande européenne à gauche, logo de
l’application à droite et département 33 en dessous.
La police et sa licence OFL sont incluses dans public/fonts ; aucun appel
à un fournisseur de polices n’est nécessaire lors de l’affichage.
L’historique des signalements et les litiges reprennent la même présentation
en format compact, sans agrandir les cartes.
AQ610RK devient visuellement AQ-610-RK. Les formats étrangers et anciens
conservent leur texte. Aucune immatriculation stockée n’est réécrite.
La photo de référence n’était pas disponible dans le message reçu :
la police est une proposition visuelle proche, pas une reproduction vérifiée
sur cette photo.

4 — DÉBRIEF IA ET VOIX : ACTIVATION PAS À PAS
Une nouvelle fonction Edge est fournie : workshop-debrief.
Il n’est pas nécessaire de redéployer workshop-push ou workshop-accounts.

A. Clé API OpenAI
- Ouvre https://platform.openai.com/api-keys dans ton compte OpenAI.
- Crée une clé API pour ce projet et garde-la privée.
- Active la facturation API et configure un budget adapté à ton usage.
  Les générations de texte et de voix utilisent une API facturée.
- Supabase > Edge Functions > Secrets : ajoute
  OPENAI_API_KEY = ta clé API OpenAI.
- Ne mets jamais cette clé dans GitHub, le code du site ou une variable VITE.

B. Fonction Supabase
- Ouvre Supabase > Edge Functions > Deploy a new function > Via Editor
  (les libellés peuvent être traduits selon ton interface).
- Nomme la fonction exactement : workshop-debrief.
- Dans index.ts, remplace tout le contenu par celui de :
  supabase/functions/workshop-debrief/index.ts
- Déploie la fonction.
- Dans ses paramètres, désactive la vérification JWT automatique du service
  si elle est activée. La fonction vérifie elle-même le jeton avec
  auth.getUser, puis les droits et la publication du récapitulatif en SQL.
  Aucun accès anonyme au débrief n’est autorisé.
- SUPABASE_URL et SUPABASE_SERVICE_ROLE_KEY sont fournis automatiquement
  par Supabase. Ne les recopie pas dans le site.

Avec la CLI Supabase, l’équivalent est :
  supabase functions deploy workshop-debrief --no-verify-jwt
Le fichier supabase/config.toml contient également ce réglage.

C. Modèles configurables, facultatif
Par défaut, la fonction utilise :
  texte : gpt-4.1-mini
  voix : gpt-4o-mini-tts-2025-12-15, voix coral
Ces modèles dépendent de leur disponibilité sur ton compte API.
Tu peux remplacer les valeurs via les secrets Supabase :
  OPENAI_DEBRIEF_MODEL
  OPENAI_TTS_MODEL
Le modèle texte doit accepter Responses API ; le modèle vocal doit accepter
Audio Speech et les instructions de lecture. Aucun changement Cloudflare
n’est requis pour ces secrets. Les résultats déjà générés restent conservés.

D. Utilisation dans l’application
- Ouvre Récapitulatif puis une fiche accessible à ton compte.
- Clique sur « Générer / consulter le débrief ».
- La synthèse présente la situation, les priorités et les points à confirmer.
- Clique sur « Préparer la lecture vocale IA », puis sur Lecture dans le
  lecteur audio. Pause et reprise sont disponibles dans ce lecteur.
- La mention « Voix générée par IA » reste visible.

À la première génération, les véhicules immobilisés, les pièces manquantes
et les tâches du récapitulatif sont transmis à OpenAI. Cela peut contenir
les plaques, noms et informations que tu as saisis dans ces rubriques.
Le texte du débrief est transmis pour produire la voix. Les photos,
signatures et données des autres pages ne sont pas envoyées par cette fonction.
L’application demande de ne pas inventer de faits ; vérifie néanmoins
les points importants dans la fiche source.

Le texte et l’audio sont conservés dans Supabase pour chaque version du
récapitulatif et réutilisés lors des consultations autorisées. Une correction
du récapitulatif rend nécessaire une nouvelle génération pour sa nouvelle
version. Les droits et l’horaire de publication habituels sont respectés.
Les requêtes simultanées sont verrouillées ; 10 tentatives maximum sont
permises par version, afin de limiter les appels en cas d’erreur.
En cas de service indisponible, attends deux minutes avant de réessayer.
Après 10 tentatives échouées, corrige d’abord la cause (clé, facturation,
modèle), puis l’administrateur peut réinitialiser uniquement les compteurs
nécessaires dans SQL Editor, par exemple pour une date/version précises :
  update public.workshop_debriefs
  set attempts=0,lease=null,lease_until=null
  where date='2026-10-15' and version=1;
Adapte la date et la version à la fiche concernée.

Documentation de l’intégration :
https://developers.openai.com/api/docs/guides/text
https://developers.openai.com/api/docs/guides/text-to-speech
https://developers.openai.com/api/docs/models/gpt-4.1-mini
