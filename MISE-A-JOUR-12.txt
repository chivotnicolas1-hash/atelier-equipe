ATELIER FAYET 33 — NOTIFICATIONS ANNONCES ET TÂCHES

Cette configuration est à faire une fois. La publication du ZIP seule ne suffit pas.
La migration 11 doit déjà être appliquée. Les notifications antérieures à cette installation ne sont pas envoyées rétroactivement.

1 — GÉNÉRER TES CLÉS (SUR TON ORDINATEUR)
Ouvre outils/generer-cles-notifications.html dans Chrome ou Edge.
Clique Générer mes clés. Garde cette fenêtre ouverte et conserve les trois valeurs dans un endroit sûr. Le générateur ne transmet rien sur Internet.
Ne publie jamais VAPID_PRIVATE_KEY ou PUSH_CRON_SECRET sur GitHub ni dans Cloudflare. Ne régénère pas les clés après inscription des téléphones.

2 — SUPABASE : BASE DE DONNÉES
SQL Editor > New query : colle tout le fichier supabase/12-notifications.sql, puis Run.
Attends Success. Ce script peut être réexécuté sans supprimer les abonnements.

3 — SUPABASE : SECRETS DE LA FONCTION
Dans Edge Functions > Secrets, ajoute :
VAPID_PUBLIC_KEY = clé publique générée
VAPID_PRIVATE_KEY = clé privée générée
PUSH_CRON_SECRET = secret généré
SUPABASE_URL et SUPABASE_SERVICE_ROLE_KEY sont fournis automatiquement par Supabase à la fonction ; ne les copie pas dans le code du site.

4 — SUPABASE : NOUVELLE FONCTION
Dans Edge Functions, crée/déploie une fonction nommée exactement workshop-push.
Colle le contenu de supabase/functions/workshop-push/index.ts dans son éditeur.
Déploie, puis désactive la vérification JWT de la plateforme pour CETTE fonction (Verify JWT / Enforce JWT Verification). La fonction vérifie elle-même le secret x-workshop-secret. Ne modifie pas workshop-accounts.
Alternative avec la CLI, depuis le dossier du projet :
npx supabase functions deploy workshop-push --project-ref ifzdtnysccmcjfpnqyze --no-verify-jwt

5 — SUPABASE : ENVOI AUTOMATIQUE TOUTES LES MINUTES
Dans Vault, crée un secret nommé workshop_push_cron_secret.
Sa valeur doit être exactement la même que PUSH_CRON_SECRET de l’étape 3.
Puis dans SQL Editor, exécute supabase/12b-programmer-notifications.sql.
Le script active pg_cron et pg_net et programme atelier-notifications chaque minute.
Il utilise le secret stocké dans Vault : aucune clé privée n’est écrite dans le script.
Une réexécution met à jour le même programme, sans créer plusieurs tâches.

6 — CLOUDFLARE
Dans les variables de BUILD du projet atelier-equipe, ajoute :
VITE_VAPID_PUBLIC_KEY = la même clé publique que VAPID_PUBLIC_KEY.
Cette valeur est publique, c’est normal. La clé privée reste uniquement dans Supabase.
Enregistre avant de déployer le nouveau code.

8 — CHAQUE COLLABORATEUR, ADMINISTRATEUR ET MODÉRATEUR
Ouvre son profil, clique Activer les notifications puis Autoriser sur le téléphone.
Sur iPhone : iOS 16.4 minimum, ajouter l’application à l’écran d’accueil depuis Safari et l’ouvrir depuis cette icône avant l’activation.
L’activation est nécessaire sur CHAQUE appareil. Elle ne peut pas être imposée si la personne refuse l’autorisation du téléphone.
Après une déconnexion volontaire, cet appareil est désinscrit pour protéger les comptes sur les téléphones partagés. Le réactiver à la prochaine connexion.

9 — TEST RÉEL
Inscris d’abord ton propre téléphone. Ferme l’application.
Depuis un autre appareil, publie une nouvelle annonce visible : une notification devrait arriver après environ une minute, selon le réseau et les réglages du téléphone.
Crée ensuite une tâche pour ton propre collaborateur : vérifie la notification et l’ouverture du menu Tâches.
Dans Administration > Équipes, consulte Notifications de l’équipe puis Actualiser.
Le nombre d’appareils inscrits ne prouve pas la réception ni la lecture.

COMPORTEMENT
- Annonce activée ou texte/lien modifié lorsqu’elle est visible : toute l’équipe active inscrite, tous rôles compris.
- Enregistrer une annonce identique ou la masquer : pas d’envoi.
- Tâche créée, titre/détail/échéance/priorité/affectation modifié, ou rouverte : destinataire actuel uniquement.
- Une tâche terminée ou supprimée n’envoie pas de notification. Pas de rappel automatique d’échéance dans cette version.
- Aucune sélection manuelle de personnes pour les annonces.
- Texte discret sur l’écran verrouillé ; ouvrir l’application pour les détails.
- Le clic sur une annonce ouvre l’accueil, sur une tâche ouvre Tâches.
- Les envois sont traités par lots de 50. Cinq tentatives maximum en cas d’erreur ; abandon après 24 heures. Les abonnements expirés (404/410) sont retirés.
- Historique technique de la file supprimé après sept jours. Pas d’accusé de lecture.
- Une coupure après envoi mais avant confirmation peut provoquer une nouvelle tentative ; le même identifiant de notification limite les doublons affichés.

SI RIEN N’ARRIVE
Vérifie l’autorisation téléphone, mode Concentration/Ne pas déranger, connexion, installation iPhone.
Vérifie les trois secrets, la clé publique Cloudflare et le dernier déploiement.
Dans Supabase, contrôle l’exécution du job Cron atelier-notifications et les logs de workshop-push : 401 signifie secret incorrect ou vérification JWT encore active ; 503 configuration manquante.
Contrôle la file dans Table Editor > workshop_push_queue : sent_at = fournisseur ayant accepté l’envoi (pas preuve de lecture), last_error = erreur éventuelle.
Pour arrêter l’envoi automatique : select cron.unschedule('atelier-notifications');

VALIDATION
Compilation et tests locaux des permissions, des déclencheurs, du ciblage et de la file d’envoi. Les envois réels nécessitent tes clés, le déploiement et l’autorisation d’un téléphone ; ils ne sont pas testés sur ton service par cette archive.
