ATELIER FAYET 33 — MISE À JOUR 44
Cette archive met à jour une application déjà à jour en MAJ43.

1 — SUPABASE EN PREMIER
Ouvre ton projet Supabase > SQL Editor > New query.
Ouvre supabase/44-signatures-presence.sql depuis cette archive.
Copie tout son contenu, colle-le dans SQL Editor, puis clique sur Run.
Attends le message de réussite. Le script peut être réexécuté.
Il conserve les données existantes.

2 — GITHUB ET CLOUDFLARE
Décompresse le ZIP. Remplace les fichiers du projet GitHub par ceux de
l’archive (src, public, supabase, index.html et les fichiers de configuration).
Les fichiers de configuration sont package.json, package-lock.json,
tsconfig.json, vite.config.ts et postcss.config.js.
Supprime les anciens guides de mise à jour et les anciens scripts SQL du dépôt
si tu souhaites conserver le dépôt aussi épuré que cette archive.
Supprimer un ancien fichier SQL de GitHub n’efface pas les données Supabase.
Conserve toutes les variables de build Cloudflare déjà configurées.
N’ajoute aucun fichier _redirects. Ne publie aucune clé privée.
Attends le déploiement réussi, puis ferme et rouvre l’application.
Le pied de page doit indiquer MAJ44.
Aucun redéploiement des Edge Functions n’est nécessaire pour cette mise à jour.

3 — CONTRÔLER UNE SIGNATURE
Administrateur uniquement : Équipes > Gérer le profil > Contrôler la signature.
Vérifie le dessin, puis Supprimer la signature > Confirmer la suppression.
L’utilisateur devra tracer une nouvelle signature pour accéder à l’application.
Le contrôle se fait à l’ouverture, au retour sur l’application et toutes les
30 secondes lorsqu’elle reste ouverte.
Les signatures déjà intégrées aux anciens signalements sont conservées.
La suppression est protégée côté Supabase, pas seulement par le bouton.

4 — AFFICHER LE MOT DE PASSE
Mon profil > modifier le mot de passe : chaque champ dispose d’un bouton œil.
Il affiche ou masque uniquement le champ concerné, sans modifier sa valeur.

5 — CHANGER DE POSTE EN CONSERVANT LA PRÉSENCE
Un changement de pôle ou de pont effectué par un administrateur ou un modérateur
conserve l’heure de confirmation pour le même collaborateur et la même journée.
C’est aussi le cas après retrait de l’affectation puis nouvelle affectation.
Passer le collaborateur en absence efface toujours sa confirmation.
La confirmation n’est pas transférée à une autre journée.

6 — NOUVELLE PRÉSENTATION
Présentation harmonisée des pages, formulaires, cartes et fenêtres en mode
clair et sombre, sur ordinateur et téléphone.
Titres adaptés à chaque page, navigation plus compacte, actions des profils
regroupées et informations du jour concentrées sur l’accueil et le plan.
Les compteurs de tâches restent également disponibles sur la page Tâches.
L’import du planning reste accessible depuis le plan administrateur.
La disposition et les fonctionnalités des postes sont conservées.
Les couleurs métier restent visibles : objectif vert, urgences rouges,
WorkOrder vert. Les réglages de thème existants sont conservés.

VÉRIFICATIONS
Compilation TypeScript/Vite et tests locaux de base de données effectués.
Parcours d’interface vérifiés avec données de test pour administrateur,
modérateur, collaborateur et invité, sur mobile et ordinateur.
Le déploiement sur ton compte Cloudflare reste à effectuer avec les étapes ci-dessus.
