ATELIER FAYET 33 — MISE À JOUR 34
Notifications, mots de passe et plan mobile expérimental

À INSTALLER APRÈS LA MAJ33
Cette archive contient le projet complet. Elle n’est pas déployée automatiquement.
Les notifications réelles nécessitent ton cron et tes clés VAPID déjà configurés.

1 — REDÉPLOYER DEUX FONCTIONS SUPABASE
Dans ton projet Supabase, ouvre Edge Functions.

A. Ouvre la fonction existante workshop-push, puis son éditeur de code.
Remplace le contenu de index.ts par celui du fichier :
supabase/functions/workshop-push/index.ts
Enregistre et déploie la fonction mise à jour.
Conserve la vérification JWT désactivée : cette fonction vérifie elle-même
le secret PUSH_CRON_SECRET envoyé par ton programme automatique.

B. Ouvre workshop-accounts et remplace son index.ts par :
supabase/functions/workshop-accounts/index.ts
Enregistre et déploie cette fonction également.
Conserve la vérification JWT désactivée dans les réglages de la fonction :
le code vérifie le jeton utilisateur avec auth.getUser puis les droits SQL.

Il faut modifier LES DEUX fonctions. Une mise à jour du dépôt GitHub seule
ne redéploie pas les fonctions Supabase.
Ne change pas tes secrets VAPID ni PUSH_CRON_SECRET et ne les mets pas sur GitHub.

2 — EXÉCUTER LA MIGRATION SQL
Supabase > SQL Editor > nouvelle requête.
Ouvre supabase/34-notifications-comptes.sql, copie tout son contenu,
colle-le dans l’éditeur puis exécute-le.
Le script est réexécutable ; les données et les précédentes fonctions sont conservées.
Les migrations antérieures doivent déjà être installées.

Le cron atelier-notifications déjà créé à la MAJ12 appelle workshop-push
chaque minute. La nouvelle préparation des notifications se fait pendant
cet appel : aucun nouveau cron ni secret n’est nécessaire.
Pour vérifier la présence du programme, tu peux exécuter :
select jobname, schedule, active from cron.job
where jobname = 'atelier-notifications';
Le résultat attendu est un programme actif avec la fréquence * * * * *.
S’il n’existe pas, reprends l’installation de la MAJ12 et son script
12b-programmer-notifications.sql ; ne crée pas plusieurs programmes identiques.

3 — METTRE À JOUR GITHUB ET CLOUDFLARE
Décompresse le ZIP, remplace les fichiers du projet GitHub par ceux de
l’archive (src, public, supabase, index.html et fichiers de configuration).
Conserve les variables de build Cloudflare déjà en place.
Attends la réussite du déploiement, puis ferme et rouvre l’application.
Aucun fichier _redirects ne doit être ajouté.

4 — RÉCAPITULATIF ET RAPPELS
À partir de 7 h 30, heure de Paris :
« Le récapitulatif de la veille est disponible »
Il faut qu’un récapitulatif ait été enregistré pour la veille.
L’administrateur et les modérateurs le reçoivent une fois chacun ; chaque
appareil abonné de ces comptes peut afficher la notification.

À partir de 18 h 30, heure de Paris :
« Pense à faire ton récapitulatif »
Le rappel est envoyé si le récapitulatif du jour n’est pas déjà enregistré.
Il est envoyé chaque jour, y compris le week-end, sans filtre d’horaires.
Le changement heure d’été / heure d’hiver est pris en compte.
L’envoi démarre au passage du cron ; l’arrivée sur le téléphone dépend
ensuite de sa connexion et des autorisations de notification.

Dans le menu, Récapitulatif clignote lorsqu’une publication n’a pas encore
été ouverte par le compte connecté. L’ouverture de la page l’arrête.
L’état de lecture est conservé côté serveur et synchronisé entre appareils.
Une nouvelle publication relance l’indicateur. Pour les appareils qui
réduisent les animations, un contour et la mention Nouveau remplacent
le clignotement. Les rubriques Anomalies sont retirées du formulaire et
de l’affichage ; les anciens textes restent conservés dans la base.
Des pictogrammes sont ajoutés à Sondages et Récapitulatif.

5 — NOUVELLE PAGE NOTIFICATIONS
Chaque compte peut consulter ses propres notifications dans le menu.
Les messages restent disponibles dans cette page même si les notifications
sur le téléphone sont désactivées. Les 100 derniers messages sont affichés.
Un clic sur la notification de récapitulatif ouvre directement sa page.

Administrateur ou modérateur > Notifications > Envoyer une notification :
- sélectionner une personne, plusieurs personnes, une équipe ou tout le monde ;
- ajuster les cases des destinataires si nécessaire ;
- saisir le message (500 caractères maximum), puis envoyer.
Les collaborateurs sans compte de connexion sont ignorés et le nombre
réel de destinataires est indiqué. Les comptes invités peuvent lire les
messages adressés à leur compte, mais ne peuvent pas en envoyer ; leur
accès aux notifications push reste désactivé comme précédemment.

6 — MOT DE PASSE OUBLIÉ
Sur la page de connexion, cliquer Mot de passe oublié ?, renseigner
l’adresse du compte puis Demander un nouveau mot de passe.
La demande ne remplace pas immédiatement le mot de passe.
Si l’administrateur a des créneaux horaires renseignés pour la journée
courante à Paris, la demande lui est adressée. Sinon elle est adressée
aux modérateurs actifs. S’il n’y a pas de modérateur, l’administrateur
reste le destinataire de secours. Les horaires PDF et manuels sont utilisés.
L’administrateur peut toujours consulter toutes les demandes ouvertes.

Pour la traiter : Notifications > Demandes de mot de passe > Traiter la demande.
Vérifier l’identité de la personne, saisir un nouveau mot de passe de
12 à 128 caractères, cocher la confirmation, puis valider.
Communiquer le nouveau mot de passe directement au collaborateur :
aucun mot de passe n’est inclus dans une notification ou enregistré dans
la table de demandes. Le collaborateur pourra ensuite le changer lui-même.
Un modérateur ne peut traiter que les demandes qui lui ont été attribuées
et ne peut pas remplacer le mot de passe de l’administrateur.
Si l’administrateur perd lui-même son accès, utiliser la récupération du
compte depuis Supabase ; cette fonction ne délègue pas son compte aux modérateurs.
Les demandes répétées sont limitées et la page de connexion ne révèle
pas si l’adresse saisie existe dans l’équipe.

7 — MODIFIER SON PROPRE MOT DE PASSE
Mon profil > Modifier mon mot de passe.
Saisir le mot de passe actuel, le nouveau et sa confirmation.
Disponible pour tous les comptes, y compris l’invité.
Le changement utilise le service Auth de Supabase. Si une vérification
supplémentaire est demandée par Supabase, se déconnecter puis se reconnecter
avant de réessayer. Les autres collaborateurs ne sont pas affectés.
Documentation de l’API utilisée :
https://supabase.com/docs/reference/javascript/auth-updateuser

8 — ICÔNE MOBILE
Le fond bleu remplit maintenant l’icône et ses coins ; le logo est agrandi.
Une version adaptée au masque du téléphone conserve une marge bleue de
protection pour les lettres, sans cadre blanc.
Les nouveaux fichiers portent v34 pour faciliter leur actualisation.
Le logo affiché dans la barre de l’application reste inchangé.
Si le téléphone garde l’ancienne icône, supprimer l’ancien raccourci ou
l’installation PWA puis réinstaller depuis le navigateur. Les informations
restent dans Supabase. Réactiver les notifications sur cet appareil si nécessaire.
La forme finale (rond, carré arrondi…) dépend du lanceur du téléphone.

9 — PLAN MOBILE V2, ADMINISTRATEUR UNIQUEMENT
Dans le mode Administration, choisir Plan mobile V2 dans le menu.
Les postes sont présentés en grandes cartes, sur une colonne sur petit
écran et deux colonnes sur les écrans plus larges, sans défilement horizontal.
Les affectations, doubles postes, coupures déjeuner, confirmations,
horaires, numéros et noms personnalisés restent ceux du plan actuel.
Cliquer sur un poste ouvre le même panneau d’affectation.
Le sélecteur de date et L’équipe du jour restent disponibles.
ATTENTION : ce sont les vraies données. Une modification faite sur le
plan V2 est aussi visible sur le plan actuel ; il s’agit d’une nouvelle
présentation, pas d’un environnement de simulation.
Le menu et la page V2 sont masqués pour les modérateurs, collaborateurs
et invités. Le plan habituel reste accessible comme avant.
