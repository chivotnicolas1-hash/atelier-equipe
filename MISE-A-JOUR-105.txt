INSTALLATION DEPUIS LA VERSION 104
Cette archive est une mise à jour du projet existant, pas une installation
sur une base Supabase vide. Le SQL de la version 104 doit déjà être installé.
Aucun nouveau SQL et aucune Edge Function à déployer pour cette version.

1. Remplace les fichiers du projet GitHub par ceux de cette archive.
   Conserve tes variables de build Cloudflare.
2. Supprime src/visibility-choice91.tsx s’il reste dans ton dépôt : ce

CORRECTIF
L’option « Réservé à l’administrateur et aux modérateurs » utilisait une
écriture automatique indépendante de l’enregistrement des autres champs.
Elle est maintenant préparée dans la fiche puis enregistrée avec son bouton
principal, dans la même opération que le nom, le code, la photo et le stock.
Dans le plan des huiles, cette option est enregistrée avec le plan et les codes.
Cocher ou décocher la case ne lance donc plus de sauvegarde séparée.
Annuler ou fermer sans enregistrer ne change pas cette option en base.

Les anciennes réponses de synchronisation ne peuvent plus remplacer les
données d’une fiche en cours d’édition. Le plan des huiles possède aussi un
contrôle de l’ordre des réponses : une lecture partie avant l’édition ou la
sauvegarde est ignorée lorsqu’elle arrive en retard. Une erreur issue de cette
ancienne lecture n’efface pas le résultat de l’enregistrement.
L’actualisation du reste de l’application toutes les 20 secondes est conservée.
Les contrôles de version et les droits côté Supabase sont conservés.
Les messages de sauvegarde et la limite d’attente de 30 secondes de la
version 104 restent actifs pour l’enregistrement principal.

ESSAI
Modifier le catalogue > ouvrir un produit > cocher la restriction >
Enregistrer les modifications. Refaire l’essai sur un deuxième produit,
puis décocher la restriction sur le premier et enregistrer à nouveau.
Rouvrir les fiches pour vérifier. Tu peux laisser la page ouverte pendant
plus de 20 secondes entre ces étapes pour inclure la synchronisation.
