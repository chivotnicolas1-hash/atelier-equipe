ATELIER FAYET 33 — MISE À JOUR 103

INSTALLATION (depuis la version 102)
1. Dans Supabase > SQL Editor, ouvre et exécute entièrement :
   supabase/103-conges-consommables.sql
   Attends le message de réussite avant la suite.
2. Remplace les fichiers du projet GitHub avec ceux de cette archive :
   src, public, supabase et les fichiers de configuration à la racine.
   Conserve les variables de build déjà présentes dans Cloudflare.
   Aucun fichier _redirects ne doit être ajouté.
3. Attends la réussite du déploiement Cloudflare, puis ferme et rouvre
   l’application. Si nécessaire, actualise une fois la page.
Aucune Edge Function supplémentaire à déployer pour cette mise à jour.
Les fonctions de la mise à jour 100 restent nécessaires si elle n’a pas
encore été installée. Cette archive suppose la base à jour jusqu’à 102.
Ne réexécute pas les anciennes migrations après la 103 : elles pourraient
remplacer les fonctions corrigées. Les anciens guides sont conservés pour
référence et ne sont pas des étapes à répéter.

RACK DÉCHETS
Le libellé « vide » héritait du style d’une page vide : 60 px de marge
intérieure au-dessus et au-dessous. Ce conflit de style est corrigé.
La hauteur du titre est également compactée et les retours à la ligne
superflus ne sont plus affichés dans le titre. Le contenu saisi est conservé.

CONGÉS ET ABSENCES
Les administrateurs et modérateurs disposent de deux dossiers :
- Mes congés : demandes personnelles, avec les règles habituelles.
- Congés de mon équipe : toutes les demandes de l’équipe, y compris
  leurs propres demandes lorsqu’elles sont dans cette liste.
L’administrateur peut décider, modifier et supprimer les demandes.
Le modérateur peut consulter et exporter les demandes de l’équipe,
mais ne dispose d’aucune action d’écriture dans le dossier de l’équipe.
Il conserve la gestion de ses propres demandes dans « Mes congés »,
selon leur statut et les règles déjà en place.
Le calendrier d’équipe reste réservé à l’administrateur.

Le bouton « Absence exceptionnelle » ouvre un formulaire avec :
- début et fin inclus ;
- motif obligatoire ;
- case « Possibilité de changer mon repos pour ce jour » ;
- confirmation d’envoi avec la signature enregistrée.
La case est une proposition transmise au responsable : elle ne déplace
pas automatiquement un repos et ne modifie pas le planning.
La demande suit les mêmes étapes de décision que les congés.
Le type, le motif et le choix concernant le repos sont consultables.
Ils sont repris dans l’export PDF existant.
Une modification de ces informations par l’administrateur utilise le
circuit existant de nouvelle signature lorsque celle-ci doit être renouvelée.

CONSOMMABLES
Les noms et descriptions des sections sont enregistrés avec un contrôle
de version et le nouvel état est immédiatement repris par l’application.
Les sections récentes sont prises en charge. Les autres réglages existants,
notamment les rappels, sont conservés.
Une modification concurrente n’est pas écrasée silencieusement : ferme
puis rouvre l’éditeur si le catalogue ou les réglages ont changé ailleurs.

Pour un produit de catalogue sans photo, « Choisir une image existante »
permet de sélectionner une image puis de l’enregistrer sur ce produit.
Le serveur copie l’image déjà stockée à partir du produit source ; celui-ci
reste intact. La sauvegarde des autres champs et de la photo est atomique.
Les images choisies sont également normalisées pour les autres formulaires
qui réutilisent cette galerie.
