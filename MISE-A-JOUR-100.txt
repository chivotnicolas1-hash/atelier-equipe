ATELIER FAYET 33 — MISE À JOUR 100
ID personnalisés, consommables et suivi des déchets

LIRE CE GUIDE AVANT D'INSTALLER : LA CONNEXION CHANGE
Cette mise à jour s'applique à ta base actuelle, d'après le diagnostic transmis.
Ne réinitialise aucun compte Auth. Les UUID et mots de passe existants sont
conservés, donc les signatures, photos, historiques et demandes restent liés.
Installe les SQL ET les deux Edge Functions avant d'utiliser le nouveau site.

1 — SQL SUPABASE
Garde ton mot de passe administrateur actuel à disposition.
Dans SQL Editor > New query, exécute dans cet ordre :
  supabase/100a-identifiants.sql
  supabase/100b-consommables-dechets.sql
Une erreur annule le script concerné : copie son message avant de poursuivre.
Ne réexécute pas les anciens SQL93/94/98 après le SQL100.

Le SQL100a efface les anciennes valeurs de matricules et crée des ID de
transition. Ils ne sont ni des mots de passe ni des matricules récupérés.
TON ID INITIAL ADMINISTRATEUR : ATELIER-ADMIN
TON MOT DE PASSE : inchangé.
Les autres ID de transition commencent par AF33-. Tu peux les modifier dans
Équipes > Modifier la fiche > ID de connexion personnalisé.
ID unique de 3 à 32 lettres, chiffres, tirets ou underscores, sans espace.
Les ID sont normalisés en majuscules, la connexion ignore la casse.
Les scripts sont réexécutables sans recréer les ID déjà personnalisés.
Si tu oublies un ID, le SQL100c permet de le relire dans SQL Editor.
Une erreur de connexion juste après installation impose de vérifier en premier
le déploiement de workshop-login ; ne recrée pas ton compte administrateur.

2 — DÉPLOYER LES EDGE FUNCTIONS
Dans Supabase > Edge Functions, ouvre workshop-login.
Dans son code, remplace index.ts par le contenu du fichier
supabase/functions/workshop-login/index.ts de cette archive, puis Deploy.
Fais la même chose pour workshop-accounts avec son fichier index.ts fourni.
Ces deux fonctions doivent conserver verify_jwt = false : elles assurent leur
vérification elles-mêmes (workshop-login vérifie le mot de passe via Auth,
workshop-accounts vérifie le jeton utilisateur puis les droits SQL).
Le fichier supabase/config.toml contient les réglages à garder.
Ne désactive pas le fournisseur Email dans Supabase Auth : il reste le moteur
technique interne de l'authentification par mot de passe.
Aucune nouvelle clé ni aucun nouveau secret à ajouter. Les clés de service
restent exclusivement dans Supabase, jamais dans GitHub ni dans une variable VITE.
La fonction workshop-push n'a pas changé ; inutile de la redéployer pour la 100.

3 — GITHUB ET CLOUDFLARE
Remplace src, public, index.html, package.json, package-lock.json,
tsconfig.json, vite.config.ts et postcss.config.js par les fichiers fournis.
Conserve tes variables de build Cloudflare. Aucun fichier _redirects à ajouter.
Attends la réussite du déploiement, puis ferme et rouvre l'application.
Connecte-toi avec ATELIER-ADMIN et ton mot de passe habituel.
Les anciens clients peuvent nécessiter une réouverture pour récupérer ce code.

4 — PERSONNALISER LES ID ET REMPLACER LES ANCIENNES COORDONNÉES
Dans Équipes, vérifie les ID affichés. Modifie-les dans les fiches selon ton choix
et transmets à chacun son nouvel ID. Si tu changes le tien, note-le avant
la prochaine déconnexion. Les mots de passe ne changent pas.
Ouvre « Identifiants et suppression des anciennes coordonnées ».
Après vérification, clique sur « Supprimer les anciennes coordonnées ».
Cette action remplace les adresses personnelles par des alias techniques
aléatoires @atelier.invalid dans les comptes liés aux fiches atelier.
Elle ne crée pas de boîte mail. Aucun mail n'est nécessaire aux collaborateurs.
Les remplacements passent par l'API officielle Auth ; le serveur nettoie ensuite
les coordonnées correspondantes dans les champs texte/JSON des tables actives
public et workshop_private. Les comptes Auth restent les mêmes UUID.
Si un compte échoue, les autres déjà migrés restent migrés : corrige le problème
indiqué puis relance le bouton. Les comptes finalisés sont ignorés au prochain
passage. N'édite pas les fiches pendant cette opération.
Vérifie que toutes les lignes indiquent « Coordonnée remplacée ».
Ferme puis rouvre l'application pour renouveler les informations de session.

IMPORTANT — PÉRIMÈTRE DE SUPPRESSION
Les adresses fictives techniques restent nécessaires au moteur Auth.
Cette mise à jour n'efface pas les sauvegardes, journaux techniques/audit Supabase,
anciens exports, documents binaires ou fichiers déjà téléchargés. Elle ne peut
pas garantir « aucune trace dans toutes les bases et sauvegardes ».
Les comptes Auth sans fiche atelier ne sont pas supprimés automatiquement.
Le script 100c-verifier-migration.sql donne un contrôle des fiches et un nombre
de comptes Auth non associés, sans exposer de mot de passe. Si ce nombre n'est
pas nul, fais vérifier ces comptes avant de supprimer quoi que ce soit.
Les anciennes valeurs de matricule dans leur ancienne table sont effacées dès
le SQL100a ; aucun matricule n'est réutilisé pour générer les nouveaux ID.

5 — CONSOMMABLES EN RUPTURE
Un collaborateur ne peut pas ajouter ni augmenter une référence indisponible.
Dans leur espace de gestion, administrateur et modérateurs peuvent la remettre
en commande, sans devoir déclarer le produit disponible dans le catalogue.
Cette autorisation ne remet pas automatiquement le stock du catalogue à jour.
La règle est aussi vérifiée côté base ; pas seulement dans les boutons.

6 — DATE ANNONCÉE ET CHRONOLOGIE DES DÉCHETS
Dans le suivi d'une demande, « Le prestataire a communiqué une date » permet
aux administrateur/modérateurs, et aux personnes disposant du droit de suivi,
de renseigner une date de collecte. Elle ne valide pas le ramassage lui-même.
Tant qu'une date est renseignée, les relances automatiques sont suspendues,
même si cette date est dépassée. La tâche de relance est fermée et les rappels
correspondants sont retirés de Mes notifications ; les envois encore identifiables
en attente sont annulés. Une notification déjà reçue/en cours d'envoi sur un
appareil ne peut pas être rappelée. Une ancienne file d'envoi ambiguë, partagée
avec un autre rappel encore actif, n'est pas supprimée au risque de perdre cet
autre rappel. Les nouveaux rappels incluent une référence de demande distincte.
Retire la date puis enregistre pour réactiver le suivi du délai.
La chronologie réunit création, validation, dernière modification, suivi,
relances, dates annoncées/retirées et ramassages partiels ou complets.
Les anciennes modifications non historisées par l'application ne peuvent pas
être reconstituées rétroactivement.

7 — RACK
Clique sur une case contenant un bac : choisis Non précisé, Vide ou Plein,
puis Enregistrer le contenu. Le bac plein est représenté rempli ; le bac vide
est représenté ouvert et vide. Le texte reste présent pour la lisibilité.
Les cases verrouillées restent protégées, y compris pour l'état du bac.
